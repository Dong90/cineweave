# CineWeave V0.1 Windows 离线验收与导出

本文是从干净 Windows 环境验证、运行和导出 CineWeave `v0.1.0` 的唯一操作说明。V0.1 使用未经修改的官方 Godot 4.7.2 生成 Windows x86_64 验收包；`Dong90/godot` Fork 固定为源码来源与兼容门，不需要在普通 Player、内容或文档变更中重复编译。

## 1. 依赖和磁盘空间

- Windows 10/11 x86_64、PowerShell 5.1 或更高版本、Git。
- 首次使用 `-Bootstrap` 时可访问 GitHub；脚本会在仓库外下载并校验官方 Godot 编辑器和约 1.2 GB 的官方导出模板，建议预留 4 GB 空间。后续导出复用本地缓存。
- 只有重新生成原创媒体时才需要 FFmpeg/FFprobe；正常验证和导出使用仓库内已校验的 `.ogv` 成品。
- Fork 只在 `.gitmodules` 或 `engine/**` 变化时由 CI 编译。没有引擎输入变化时，`fork-player` 明确跳过约 30 分钟编译，发布验收复用与 `engine/version.json` 固定提交绑定的已有 Fork 构建运行同一组无窗口测试；这只跳过编译，不跳过兼容验证。

所有工具缓存位于 `%LOCALAPPDATA%\CineWeave` 或 Godot 的用户模板目录；不会提交进仓库。

## 2. 干净检出和内容准备

```powershell
git clone https://github.com/Dong90/cineweave.git
Set-Location .\cineweave
git -c url.https://github.com/.insteadOf=git@github.com: submodule update --init --depth 1 engine/godot

powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\content\sync_storypacks.ps1 -Check
```

如需从固定参数重新生成全部原创媒体，再执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\media\generate_zero_echo.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\content\sync_storypacks.ps1 -Check
```

## 3. 自动测试和正常启动

首次导出最短命令如下。`-Bootstrap` 下载并校验官方 Godot 4.7.2 和 Windows Release 模板；导出前要求 Git 工作树完全干净，并自动运行内容同步检查、仓库合同、Windows 导出合同和全部 Godot 无窗口测试。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\release\export_windows.ps1 -Bootstrap
```

已经安装 Godot 时可以显式指定，且无需再次联网：

```powershell
$env:GODOT_BIN = 'C:\Tools\Godot_v4.7.2-stable_win64_console.exe'
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\run_headless.ps1 -GodotPath $env:GODOT_BIN
& $env:GODOT_BIN --path .\apps\player-godot
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\release\export_windows.ps1 -GodotPath $env:GODOT_BIN
```

重复生成同一路径时增加 `-Force`。该参数只替换传入的精确输出目录，默认输出仍在已忽略的 `dist/` 下：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\release\export_windows.ps1 -Bootstrap -Force
```

每次 `run_headless.ps1` 都会复制一个不含 `.godot` 的临时 Player 工程，因此官方版和 Fork 可以连续执行而不会互相污染导入缓存。V0.1 发布记录必须同时保留当前源码在官方 4.7.2 和固定 Fork 上的通过证据；若已有与 `engine/version.json` 同一源码提交、且 console/GUI 哈希与 `tools/godot/fork-windows-artifacts.json` 一致的 Fork 二进制，可以直接复用。`verify_fork_compatibility.ps1` 会先校验 Submodule 提交、内嵌版本和两份二进制哈希，再运行同一组无窗口测试：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\verify_fork_compatibility.ps1 -ForkGodotPath .\engine\godot\bin\godot.windows.editor.dev.x86_64.console.exe
```

只有 `.gitmodules`、`engine/**` 确有变化，或不存在这份已固定构建时，才重新编译 Fork。重新构建后必须在同一个引擎变更 Ticket 中更新构建哈希锁并再次执行上述验证；不能把任意同名 Godot 当作 Fork：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\engine\build.ps1 -Bootstrap -Jobs 2 -DevBuild
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\verify_fork_compatibility.ps1 -ForkGodotPath .\engine\godot\bin\godot.windows.editor.dev.x86_64.console.exe
```

## 4. 导出结果和自动验收

默认结果为：

```text
dist/CineWeave-v0.1.0-windows-x86_64/
├─ CineWeave.exe
├─ CineWeave.pck
├─ README.txt
├─ BUILD-EVIDENCE.json
├─ SHA256SUMS.txt
└─ licenses/
```

导出脚本会自动调用下列独立验收入口，也可以对已有结果重复执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\verify_windows_export.ps1
```

验收会核对精确文件集合、所有文件 SHA-256、构建身份、当前干净源码提交、官方 Godot/Fork 固定身份、PE x86_64 架构、Godot PCK 头和许可证。官方 Godot 的控制台启动器和它实际调用的 GUI 主程序作为一对分别固定 SHA-256，防止混用其他构建。它会以正常 Windows 图形模式隐藏启动导出的程序，按真实墙钟连续观察 10 秒；程序提前退出或出现任何 TCP/UDP 端点都会失败。源码合同同时拒绝 Player 中的 HTTP、WebSocket、TCP、UDP 和遥测 API；V0.1 不包含账号、远程内容、供应商密钥或 AI 调用。这个自动检查只证明包的图形启动和启动期离线性，不冒充两次完整人工游玩。

`dist/`、`build/`、`.exe`、`.pck`、模板和缓存不进入 Git 历史。执行导出前后，`git status --short` 都必须为空；有任何已跟踪或未跟踪源码变化时脚本会拒绝生成发布证据。`BUILD-EVIDENCE.json` 使用固定 LF 和无 BOM UTF-8，且其中的 `source_commit` 必须与当前检出提交完全一致。

## 5. 断网人工体验清单

以下清单是 V0.1 发布门禁，不能由 10 秒自动启动观察替代。验收人必须在同一份候选包上断网完成两条路线，并把 `docs/release/V0.1-ACCEPTANCE.md` 复制到工作树之外，填写日期、候选提交、包哈希和结果。完成件命名为 `CineWeave-v0.1.0-ACCEPTANCE.md`，不提交回仓库，而是作为 GitHub Release 资产发布并链接到 Issue #12；因此验收记录不会反过来改变候选包的源码提交。

正式发布顺序固定为：从 `develop` 创建 `release/0.1.0`，在其干净候选提交上导出并完成全部自动门禁与两条断网路线；在工作树之外填写候选提交、源码树哈希、Fork 身份和有效载荷哈希；门禁全部通过并获得许可后，才把 release PR 以 merge commit 合入 `main`。随后在最终 `main` 提交上重新导出，必须证明源码树与已验收候选提交完全相同，且 EXE、PCK、README 和 `licenses/` 逐字节一致。payload 比较明确排除 `BUILD-EVIDENCE.json` 和 `SHA256SUMS.txt`：前者的 `source_commit` 必须更新为最终 merge commit，后者必然随证据哈希更新，两者需要在最终 `main` 上由 `verify_windows_export.ps1` 单独重新验证。证明通过后，在外部验收完成件补入最终 `main` 提交，创建指向该提交的 `v0.1.0` 标签并发布候选包、校验和与验收记录。若源码树或有效载荷有任何差异，必须回到 release 分支修复并重新执行完整验收。任一步失败都不创建正式 Release，也不移动或复用已经发布的标签。

源码树使用 `git rev-parse <candidate>^{tree}` 与 `git rev-parse <main>^{tree}` 比较；payload 使用 `Get-FileHash -Algorithm SHA256` 比较上述文件集合。候选包在合并前复制到 `dist/.acceptance/release-candidate/` 保留，避免最终重导出覆盖比较基准。

在 Windows 网络适配器断开或防火墙阻断的情况下，从同一份导出包完成两次体验：

1. 双击 `CineWeave.exe`，确认标题页为冷峻“影院极简”界面，没有 Godot 默认裸控件。
2. 开始后依次观察加载、播放、与媒体时间同步的简体中文字幕。
3. 按 `Escape` 暂停，确认视频、字幕和剧情输入冻结；继续后保持同一时间位置。
4. 在选择界面确认没有倒计时，先用鼠标选择“登上末班车”，到达“循环仍在继续”。
5. 从结局重新开始，第二次用数字键选择“离开站台”，到达“幸存者”。
6. 两条路线分别约 3 分 55 秒和 3 分 45 秒，均处于 3–5 分钟范围。
7. 分别检查重新开始、返回标题和退出；它们必须清理当前会话且不崩溃。
8. 保留 `verify_windows_export.ps1` 的无网络端点证据，并确认整个过程无需恢复网络。

无效 StoryPack、媒体缺失和媒体不可播放的故障注入由 `tests/run_headless.ps1` 通过正式 Player 错误遮罩验证：剧情停止，玩家可看到安全摘要并返回标题或退出，Release 界面不泄露本地路径。开发模式保留资源身份和诊断路径。标题、加载、播放、字幕、选择、暂停、两个结局和错误遮罩均在同一 Player 场景集成测试中覆盖。

## 7. Known limitations（已知限制）与 V0.2 承接

### 已知限制

- 仅发布 Windows x86_64、简体中文和键鼠输入；没有安装器或代码签名。
- 低码率程序化抽象媒体用于验证完整影游管线，不代表最终商业美术质量。
- 没有设置页、音量调节、手柄、存档、快进、回看、遥测、自动更新或联网功能。
- V0.1 的 Windows 验收包不是 V0.8 才正式化的 `ReleaseManifest`/不可变 `ReleaseBundle` 系统。

### V0.2 承接边界

V0.2 在不推翻本样片的前提下正式化 StoryPack 共享数据契约、DraftStoryPack/PublishedStoryPack 边界、角色与世界变量、条件、媒体引用和本地化键。V0.1 已稳定保留 `format_version`、StoryNode 身份、StoryRuntime `start/dispatch` seam、PlayerAction/StoryEffect 通道、离线媒体以及可重复导出入口；V0.2 不应把 AI、网络或草稿内容直接接入 V0.1 的运行时权威路径。
