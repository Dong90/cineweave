# 领域文档使用规则

CineWeave 当前采用单上下文领域文档结构。所有技能在探索、命名、写规格、拆任务、设计测试或评审之前，按任务相关性读取以下内容：

- 根目录 `GLOSSARY.md`：领域术语的唯一来源。
- `docs/adr/`：影响当前区域的架构决策记录；目录和 ADR 按实际决策惰性创建。
- `docs/ROADMAP.md`：版本插入、修改、冻结和发布制度。
- 根目录 `README.md`：当前产品边界和详细版本路线图。

## 使用规范术语

Issue 标题、分支名称、模块接口、测试名称、日志和 AI 提示统一使用 `GLOSSARY.md` 中的术语。术语表明确要求避免的同义词不得重新引入。

遇到缺失概念时：

1. 先确认它是否只是现有概念的同义词。
2. 如果确实是新的领域概念，使用 `/domain-modeling` 检查边界和反例。
3. 将稳定定义写入 `GLOSSARY.md`；实现细节留在代码或架构文档。

## 架构决策

影响多个核心产物、改变兼容含义或难以逆转的决定写入 `docs/adr/NNNN-<slug>.md`。如果新方案与已有 ADR 冲突，规格和评审必须明确指出冲突并说明为何需要重新开启决定，不能静默覆盖。
